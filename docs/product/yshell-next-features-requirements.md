## 0. 现状基线与能力边界

本节是后续判断的前置事实，均来自当前代码/文档核对。

### 0.1 应用与窗口架构

- Slint `=1.9.2`（winit + software renderer，`crates/yshell-app/Cargo.toml`）；**决策：升级到最新稳定版 1.18.1，MSRV 1.89→1.92（见 §12 D1）**。
- 单窗口：`bootstrap_app()` 中调用 `window.run()`（`crates/yshell-app/src/bootstrap.rs`），窗口关闭即进程退出。
- 运行时为单线程 `Rc<RefCell<AppRuntime>>`，所有 UI 回调通过 `window.as_weak()` 绑定；终端刷新由窗口上的 `Timer` 轮询驱动。
- 窗口最小 880×600、默认 1440×900；<1120px 自动折叠右栏、<960px 左栏变图标条；左右栏宽度可拖拽（仅内存态，不持久化）。

### 0.2 标签与工作区

- `AppRuntime` 已持有 `sessions: BTreeMap<String, SessionRuntime>` 与单个 `active_session_id`；`SessionRuntime` 持有终端 grid/parser、SSH shell、日志器等（`session_runtime.rs`）。
- **但 UI 只渲染当前活动会话**；标签条只有一个固定、不可关闭的标签（`ui/main_window.slint`），`ui/components/terminal_tab_bar.slint` 存在但无人引用（死代码）。
- `yshell-core::workspace_layout` 已有最多 4 pane 的切分模型（split/close/ratio），**未接线到 UI**。
- 结论：**"真实多标签系统"是本轮多数功能的硬前置**（tracker F1）。

### 0.3 面板布局

- 左侧固定为会话树；右侧为一个 Dock，内部竖向堆叠 SFTP（写死 420px 高）、Tunnels、Transfers、Quick Commands 卡片。
- 面板显隐开关散落在 CommandBar 与 View 菜单；没有"每面板选择左/右 + 栏内上下分栏比例"的模型，也没有布局持久化。

### 0.4 SFTP

- 单栏远程文件管理器（迭代 3）：路径/重命名/chmod/删除/新建目录/远程编辑已可用；双行工具栏按钮 + 状态行。
- 已知限制（设计文档自述）：无双栏/本地列表、无系统文件选择器、无拖放、无递归下载、无多选、目录大小/符号链接/时区等细节未处理。
- 后端 `SftpBackend` 只有单文件 `upload_file` / `download_file`（`crates/yshell-sftp/src/client.rs`）；`TransferQueue` 只是一个较薄的状态机，UI 只有摘要。
- 没有任何文件对话框依赖（无 `rfd`）；上传/下载靠路径文本输入。

### 0.5 认证与密钥

- SSH 连接按会话配置的**单一认证方式**直接尝试（`real.rs::authenticate_native_session`）；**没有查询服务端 `auth_methods`**，也没有"认证方式选择"流程。
- keyboard-interactive 目前只实现了"把配置里的 secret 填给所有 prompt"的简化 prompter，不支持服务端多 prompt/echo 差异。
- 已有：密码弹窗（仅本次连接）、host key 三选一弹窗、known hosts 管理页、secret store（文件型加密仓库 + OS keychain 边界，解锁依赖 `YSHELL_MASTER_PASSWORD`）。
- 没有独立的密钥清单；私钥仍以文件路径引用。

### 0.6 终端渲染与主题

- 渲染器内置 DejaVu Sans Mono、默认 16px；默认前景/背景色写死常量，ANSI 16 色为固定调色板（`yshell-terminal/src/render.rs`、`color.rs`）。
- 已支持 `with_font_size`，但没有字体切换 API；CJK 字形缺失（遗留 B1）、粗斜体未真正加载（B2）。
- 配置侧：全局 `appearance`（UI 主题模式/UI 字体/字号）与全局 `terminal`（仅 scrollback 两项）；会话可覆盖 `appearance/terminal/logging`；**文件夹没有这三类覆盖字段**；`ResolvedSessionProfile` 只做 session→global 两级解析。

### 0.7 日志

- `SessionLogger` 支持 raw/sanitized、路径模板、脱敏、轮转策略；当 `LoggingProfile.enabled` 时按 `{session_id}/{kind}-{timestamp}.log` 自动落盘（`session_runtime.rs::configure_logging`）。
- 没有"运行中为单个终端临时开启/停止日志"的入口；右键菜单设计文档里的 Logging 项尚未实现。

### 0.8 配置 schema

- `config.toml`：folders（会话树）、auth_profiles、proxy_profiles、sftp、tunnel、appearance、logging、terminal（均为全局默认），会话内可选覆盖。
- 没有 `ui`（面板布局/交互偏好）、没有快速连接历史/快速链接、没有密钥清单、没有终端配色方案。
- 改动都涉及 `schema_version` 迁移与 `store.rs` 持久化。

### 0.9 关键外部能力边界（决定若干功能的可行性）

| 能力 | 现状 | 影响 |
|---|---|---|
| Slint 应用内拖放 | 1.17 起提供 `DragArea`/`DropArea`/`data-transfer`；1.18 起 `DataTransfer` 可携带文件路径（项目当前锁定 1.9.2） | **决策：升级到 1.18.1**；SFTP 双栏、标签重排、面板停靠改用原生拖放 |
| OS 级文件拖入/拖出（资源管理器 ↔ 应用） | Slint master 已实现跨窗口/跨应用拖放（winit 后端），**依赖 winit 0.31 正式版**；winit 0.31 当前为 beta（稳定版 0.30.13） | **决策：等 winit 0.31 + Slint 跟进版本**；期间用 rfd/路径输入，DropArea 与传输流程提前就绪 |
| 多窗口 | Slint 支持：每实例 `show()` + `run_event_loop()`；globals 按实例隔离 | 当前 `run()` 单窗口需重构，见 N7 |
| 系统文件对话框 | 无依赖；`rfd` 在 Linux 需要 GTK 或 xdg-desktop-portal，WSLg 无 portal 时需降级 | **决策：rfd + 路径输入降级**；影响 SFTP 上传/下载、日志选路径、私钥导入 |
| 服务器认证方式协商 | libssh2（`ssh2` crate）提供 `Session::auth_methods()`，当前未用 | N4 的认证弹窗可行，需 SSH 层改造 |

## 2. N1 SFTP 小窗优化 + 拖动/复制

### 2.1 目标

- 在右栏最小宽度（约 280px）与最小窗口（880×600）下仍然可用、不臃肿。
- 操作入口收敛：页面只保留导航与最少按钮，其余进右键菜单/弹窗。
- 文件搬运支持：远端→本地、本地→远端；"拖动"与"复制"两种手势。

### 2.2 现状与差距

- 页面元素多：两行工具栏（Up/Refresh/Home/New Folder/Upload/Download/Edit/Rename/Delete/Chmod）+ 路径行 + 排序/隐藏开关 + 摘要行 + 远程编辑行。
- 卡片高度写死 420px（遗留 A5），小窗下挤压其他卡片。
- 只有单文件上传/下载，多选、递归、冲突处理、传输队列的暂停/重试均无 UI。
- 无本地文件列表、无拖放、无系统文件对话框。

### 2.3 需求（交互）

**紧凑形态（先交付）**

- 头部仅保留：面包屑（窄宽时折叠为 `… / 上级 / 当前`）+ `↑` + 刷新 + `⋯`（溢出菜单）。
- 行操作全部走右键菜单（沿用 `context-menu-design.md` §4 矩阵：文件/目录/空白/多选四套），菜单里再分叉到弹窗；页面里不再放 Rename/Delete/Chmod 等按钮。
- 输入类操作（新建目录、重命名、chmod、上传/下载目标）走弹窗；危险操作（删除、覆盖）走确认弹窗。
- 列表列自适应：窄宽时优先隐藏 Permissions/Modified（进 Properties 弹窗与 tooltip），Size 降级为 `-`。
- 状态信息改为"按需可见"：条目计数并入底部细行；错误用内联条 + 重试入口，不用连续弹窗；远程编辑进行时只在底部显示一条带 Save/Cancel 的细条。
- 传输队列从卡片改为可折叠抽屉/底部条：摘要一行，点开看任务，右键 pause/resume/retry/cancel/remove（对应 E-048）。
- 卡片高度改为弹性（随可用高度伸缩、内部滚动），取消 420px 固定值。

**搬运能力（已决策，见 §12）**

- 阶段 A（即可做）：
  - 上传 = 系统文件选择器（rfd，失败降级路径输入）或"粘贴本地路径 + 最近目录"弹窗；下载 = 目标目录选择 + 文件名冲突确认（覆盖/重命名/跳过）。
  - 多选（Ctrl/Shift）与批量下载/删除/chmod。
  - 递归目录下载/上传（后端需补目录遍历接口）。
  - 远端→远端复制：**支持**，采用"下载再上传"中转（复用传输队列，进度可见）。
- 阶段 B（应用内拖放，Slint 升级到 1.18.1 后）：
  - 新增**可折叠本地栏**（双栏、WinSCP 式），远端栏与本地栏之间拖动 = 复制（默认）、Ctrl 拖动 = 移动（本地内移动/远端内重命名）。
  - 应用内剪贴板：列表上 Ctrl+C/Ctrl+V 在"本地 ↔ 远端"之间复制；不承诺与系统资源管理器互通。
- 阶段 C（**已决策：等上游**）：
  - 从资源管理器拖入 / 拖出到桌面：等 **winit 0.31 正式版 + Slint 跟进版本**；本应用提前完成 `DropArea` 接线与传输流程（上传到当前远端目录；下载到拖放目标目录）。
  - 不做自研平台层（Windows `WM_DROPFILES` / OLE 拖源）。

### 2.4 模型/配置变更

- `SftpProfile` 扩展：本地默认下载目录、上传冲突策略（ask/overwrite/rename/skip）、是否显示隐藏文件、本地栏默认可见性（可折叠记忆）。
- 本地栏会话态（当前路径、排序、显隐）可与远端栏分开记忆；面板布局相关的存 `[ui.layout]`（见 N3）。
- 后端新增：`upload_dir` / `download_dir`（或由 App 层遍历调用单文件接口 + 传输队列承载进度/取消）。

### 2.5 可行性判断

- 紧凑化 + 右键/弹窗：**低风险**，纯 UI 重构。
- 文件选择器：中风险，已决策"rfd + 路径输入兜底"双轨。
- 应用内拖动：**已决策升级 Slint 1.18.1**，`DragArea`/`DropArea` + 文件路径 `DataTransfer` 可覆盖双栏拖动；主要成本在 UI 回归。
- OS 级拖入/拖出：**稳定版组合暂不可交付**（等 winit 0.31 + Slint 跟进）；先完成落点与传输链路。

### 2.6 验收要点

- 280px 宽、600px 高时无横向截断、无按钮换行溢出；主要操作 ≤ 2 次点击可达。
- 上传/下载/覆盖/删除错误都有可见反馈与重试路径。
- 拖动/复制在双栏内完成且进度可见、可取消；OS 拖放接入后同一条传输管线可用。

### 2.7 已决策（见 §12）

- Slint 升级：是（1.18.1）。
- 本地栏：SFTP 面板内可折叠本地栏（双栏），不接入 N3 停靠。
- OS 拖放：等 winit 0.31 + Slint 跟进版本，不自研平台层。
- 远端→远端复制：支持，下载再上传中转。

## 3. N2 移除顶部连接栏 + 快速连接页

### 3.1 目标

- 删除 CommandBar 中的 Quick Connect 输入框与 Connect 按钮。
- 用"快速连接页"标签承载连接入口：输入 `ssh://root@1.1.1.1:12345` 即连，不写会话；下方展示最近连接与快速链接。

### 3.2 现状与差距

- 顶部 CommandBar 有 `New Session`、Quick Connect 输入 + Connect、三个面板开关、查找/设置/更多。
- 无"欢迎/快速连接"标签页概念；Ctrl+O 聚焦的是顶部输入框。
- 最近会话只有左栏的一段文本摘要；无快速链接模型。

### 3.3 需求（交互）

- **标签页类型**：新增 `QuickConnect` 页标签（即欢迎页），与终端标签并存。
  - 应用启动无会话时默认打开该页；最后一个终端标签关闭后回到该页（不允许 0 标签）。
  - 设置项 `new_tab_mode = quick-connect | session-editor`（**默认 quick-connect**）：点击 `+` 按设置进入对应页面；Ctrl+N 仍为新会话编辑器，Ctrl+O 聚焦快速连接页输入框（若不在该页则先打开/切换）。
- **页面内容**：
  1. 大输入框（与 Quick Connect 解析同一套：`host`、`user@host`、`host:port`、`ssh://user@host:port`），Enter 直连；非法输入即时提示。
  2. "最近连接"列表：来源 = 运行时/已保存会话的最近使用 + 快速连接历史（去重、按时间倒序、**上限 20、可关闭历史、可清空**）。
  3. "快速链接"列表：用户固定（可从最近项"固定为快速链接"，可命名、重命名、删除、排序、复制链接；**只保存连接目标**）。
  4. 可选动作：连接后提供 "保存为会话…"（打开 Session Editor 预填目标）。
- **行为**：快速连接不落 `sessions` 树；快速连接产生的会话标签显示 `user@host:port` 与 `quick` 来源标识。

### 3.4 模型/配置变更

- 新增 `TabKind { Terminal(session_id), QuickConnect }`（配合 N0 的标签模型）。
- `config.toml` 新增：
  - `quick_connect.history: [{ target, last_used_at, use_count }]`（含 `enabled` 开关与上限）。
  - `quick_links: [{ id, label, target, sort_order }]`。
  - `ui.new_tab_mode`。
- 最近会话排序（已保存会话）可复用现有 session 数据 + 新记录 `last_used_at`（或仅内存态，取决于是否要持久）。

### 3.5 可行性判断

- 依赖 N0 的标签类型；解析器与连接链路复用现有 `parse_quick_connect` + `handle_quick_connect`，**低风险**。
- CommandBar 删除输入后需要同步更新：File 菜单 Quick Connect 行为、Ctrl+O、欢迎文案、tooltip 与 i18n。

### 3.6 验收要点

- 启动即见快速连接页；`ssh://root@1.1.1.1:12345` 直连成功且不出现在已保存会话。
- 最近连接/快速链接可增删改查；历史可一键清空。

### 3.7 已决策（见 §12）

- 历史：默认开启、上限 20、可关可清空（仅本地、不存凭据）。
- 快速链接：只保存连接目标（host/user/port）。
- `+` 默认打开快速连接页（设置可切换为会话编辑器）。

## 4. N3 工具面板：左右停靠 + 上下分栏 + 占比

### 4.1 目标

- 会话（Sessions）、SFTP、Tunnels、Quick Commands（以及 Transfers）统一为可停靠工具面板：
  - 每面板可自由选择放在**左栏或右栏**；
  - 左/右各为一根**独立栏**；
  - 同栏内支持**上下分栏**，分割比例可拖动；
  - 栏宽、分栏比例、面板顺序与折叠状态可持久化。

### 4.2 现状与差距

- 左栏 = 会话树（固定）；右栏 = 四张卡片（固定顺序、固定高度、SFTP 写死 420px）。
- 面板显隐为全局 bool（`session_manager_visible/sftp_visible/tunnels_visible/commands_visible`），无"位置"概念。
- 没有任何布局持久化；窄窗口只有右栏整栏自动折叠与左栏图标条两套特判逻辑。

### 4.3 需求（交互与模型）

- **面板模型**：
  - `PanelId = Sessions | Sftp | Tunnels | QuickCommands | Transfers`。
  - `PanelPlacement = Left | Right | Hidden`；每侧的可见面板构成一个竖排栈（顺序 = 用户排序）。
  - 每个面板有折叠（仅标题条）与展开两种状态；折叠钉住高度 28–32px。
- **交互**：
  - 面板标题提供 `⋯` 菜单：Move to Left / Move to Right、Collapse、Hide；也可拖拽标题移动换边/换序（Slint 1.18 用原生 `DragArea`）。
  - 每个分栏边界有 4px 拖拽把手（复用现有 nav/dock resize 模式），比例钳制（每面板最小高度如 120px，折叠态例外）。
  - 栏宽拖拽沿用现有逻辑（左 200–420、右 280–560 起步，可按新面板数量调整上限）；两个栏分别记忆。
  - 窄窗口策略需重定义：<1120px 时哪一栏折叠（优先折叠较"次要"的一侧，或记住用户上次折叠的一侧）；单侧折叠后另一侧保留；<960px 提供图标条 + 浮出面板。
  - View 菜单与 CommandBar 的开关项同步为"面板可见性/位置"的统一入口；建议 CommandBar 只留一个 "Panels" 菜单按钮，减少按钮数量（与用户"避免大量按钮"的取向一致）。
- **面板绑定语义**（重要）：
  - SFTP/Tunnels 内容跟随**活动标签的会话**；切换标签时面板内容切换（或显示空态）。
  - Transfers 为应用级（所有会话共享）。
  - Sessions/Quick Commands 为应用级。
  - 无活动会话时 SFTP/Tunnels 显示空态与连接入口。
- **持久化**：`[ui.layout]`（**全局一套，所有窗口共享**）：
  - `left = [{panel, collapsed}]`、`right = [...]`、`left_ratios = [...]`、`right_ratios = [...]`、`left_width`、`right_width`、`narrow_collapsed_side`。
  - 窗口尺寸相关的自动折叠不回写持久化（仅内存覆盖）。

### 4.4 可行性判断

- 不依赖外部库，全部在 Slint 布局 + 运行时投影内可实现；主要成本在 `ui/main_window.slint` 结构重排与现有宽度/断点逻辑的泛化（当前是单 Dock 特判）。
- 属于 `main_window.slint` "单写者"区域，需与并行 UI 线协调（见 `ui-redesign-remaining-work.md` 使用说明）。
- 与 N0 单 pane 工作区可并行；布局归属按决策取全局一套（见 §12 D8）。

### 4.5 验收要点

- 任一支持的面板可放到任意一侧；同侧多面板可上下分栏并拖动比例；重启后布局还原。
- 280px 宽单栏下内容不溢出；折叠/展开不引起窗口最小高度异常（注意 Slint 空布局会把 max 钉死的既有坑）。

### 4.6 已决策（见 §12）

- 布局持久化：全局一套（所有窗口共享）。
- Transfers：普通可停靠面板。
- 左栏隐藏保留 48px 图标条入口兜底；需要时可通过面板菜单恢复。

## 5. N4 密钥管理与认证协商

### 5.1 目标

- 新增密钥管理：**私钥**与 **host key** 两个同级、但相互独立的界面与入口；**公钥由私钥推导**（在私钥详情中查看/复制/部署），不设独立公钥管理界面。
- 连接/重连时的认证弹窗按**服务端报告的可用认证方式**展示选项（密码、密钥、agent、keyboard-interactive 等），而不是只按会话配置一种方式。

### 5.2 现状与差距

- 私钥只以文件路径引用；无私钥导入/删除、无"部署公钥到服务器"。
- host key 已有 known hosts 页（列表/详情/删除/清空，Trust Once/Save/Replace 流程），可作为"主机密钥"页增强。
- SSH 层不查询服务端认证方式；认证失败即失败，用户无法在弹窗里换方式重试。
- keyboard-interactive 只支持单一 secret。

### 5.3 需求

**私钥管理（独立入口/界面）**

- **统一导入、加密托管**（secret store）：从文件导入私钥内容；口令（passphrase）进 secret store，不落明文；首版**不做**"仅引用路径"模式。
- 首版**不做密钥生成**；做删除（被会话引用时警告）、导出/复制公钥、"测试"（解析 + 可选连接验证）。
- 列表字段：名称、类型/算法、指纹、口令状态、被哪些会话使用。

**公钥（不设独立管理界面）**

- 由私钥推导，在私钥详情中查看/复制/导出。
- "部署到服务器"：选择已连接会话 → 追加到 `~/.ssh/authorized_keys`（幂等：先比对去重）+ 修正权限（700/600）；确认弹窗说明目标主机与追加内容。

**Host Keys（主机密钥，独立入口/界面，与私钥同级）**

- 复用 known hosts 页；补：按 host:port 分组、算法与 SHA256 指纹展示（当前展示为原始 hex，可读性差）、导出/导入、清空确认文案（D3）。

**安全要求**

- 私钥内容默认不可见/不可复制；显示需二次确认；删除/导出/部署均需确认；不做"本次会话不再询问"类弱化。

**认证弹窗（按服务端能力）**

- SSH 层在握手后查询 `auth_methods` 并回传（API: `AuthenticationChallenge { allowed: [Password, PublicKey, KeyboardInteractive, Agent?], instructions? }`）；若服务端未返回列表，则回退为"尝试配置方式 + 失败后展示手动选项"。
- 弹窗内容随可用方式变化：
  - 密码：密码框 + "记住密码"（写 secret store）。
  - 公钥：密钥下拉（来自私钥清单）+ 浏览文件 + passphrase 框；本机有 ssh-agent 时提供 "Use agent"。
  - keyboard-interactive：按服务端 prompt 动态渲染（name/instruction/多 prompt/是否回显；支持多轮；支持取消）。
  - 默认选中会话配置的方式（若在允许列表内），否则第一个可用方式；允许一次弹窗内多方式重试（失败不清空已填内容、不反复重开弹窗）。
- 与现有 `PendingPasswordPrompt` 统一为一个"认证请求"状态机；host key 弹窗顺序不变（host key 校验先于认证）。

### 5.4 模型/配置变更

- 新增 `keys` 配置节：`[{ id, label, algorithm, fingerprint, public_key, secret_ref, comment }]`（私钥内容与口令只存 secret store；公钥可缓存供展示）。
- `AuthMethod::PrivateKey` 以密钥 id 引用为主（兼容历史 path 值做迁移）。
- 认证运行时状态扩展：`PendingAuthPrompt { options, selected, fields, prompts, error }`。
- 私钥解析/公钥派生建议用成熟的 `ssh-key` 类库（不做生成可避免引入随机数/加密组件）→ 过 `deny.toml` 供应链检查。
- secret store 解锁体验当前依赖环境变量（tracker R-108），本需求必须一并解决"首次使用时的解锁/创建口令"流程，否则密钥/密码"记住"无法闭环。

### 5.5 可行性判断

- `auth_methods` 查询与多方式弹窗：**中风险**，集中在 SSH 适配层 + 认证状态机。
- 私钥导入/解析、公钥派生：低到中风险，取决于依赖选型与打包体积。
- 公钥部署：可行（复用 SFTP/exec），需注意不同服务器 `authorized_keys` 权限与 shell 环境。
- 主要风险在 UX 安全边界与跨平台一致性，不在技术可行性。

### 5.6 验收要点

- 服务端仅允许 publickey 时不展示密码输入；服务端仅允许密码时不展示密钥选择；keyboard-interactive 多 prompt 能如实呈现。
- 导入私钥 + 记忆口令后，下次连接零输入完成认证；密钥管理页操作均有确认与错误反馈。
- 私钥页与 host key 页是两个独立入口；私钥详情可查看/复制/部署对应公钥；首版无生成入口。

### 5.7 已决策（见 §12）

- 私钥存储：统一导入加密托管（secret store）。
- 密钥生成：首版不做。
- 界面结构：私钥与 host key 两个同级独立入口；公钥由私钥推导，无独立管理界面。

## 6. N5 终端主题（全局/文件夹/会话 + 内置配色）

### 6.1 目标

- 可配置终端前景色、背景色（建议含光标色、选中色、16 色 ANSI 调色板）、字体与字号。
- 内置若干流行配色方案；支持自定义颜色。
- 配置层级：**会话 > 文件夹 > 全局**（字段级继承）。

### 6.2 现状与差距

- 颜色/字体/字号在渲染器内写死；无 UI、无配置。
- 文件夹无 `terminal/appearance` 覆盖字段；无 Folder Editor（只能编辑器里选文件夹），"为文件夹配置"缺少载体。
- 字体：仅内置 DejaVu Sans Mono；CJK 缺失（B1）、粗斜体未加载（B2）、DPI/组合字形问题（B5/B6）。选字体前需先解决"字形可用性"。

### 6.3 需求

**模型**

- `TerminalProfile`（全局/文件夹/会话三级，字段均可选 + 继承）：
  - `color_scheme: Option<String>`（内置 id）或内联 `colors` 覆盖；
  - `foreground/background/cursor/selection`；
  - `ansi: Option<[16 色]>`（方案内联，字段级覆盖）；
  - `font_family: Option<String>`、`font_size: Option<u16>`、`line_height: Option<f32>`（可后置）；
  - 保留现有 `scrollback_lines/scrollback_max_cells`。
- `FolderProfile` 新增 `terminal: Option<TerminalProfile>`、`logging: Option<LoggingProfile>`、`appearance: Option<AppearanceProfile>`。
- 解析顺序：从会话所在文件夹向上到根，逐字段取最近的已定义值；再到全局；再回退内置默认。
- UI 语义：每个字段三态（继承 / 显式值）、显示 resolved 值与来源（"来自：文件夹 X / 全局 / 内置"）、单字段 Reset、整组 Reset All（P-014~P-016）。

**内置配色（首版建议 6–8 套）**

- YShell Default（现暗色）、Dracula、Nord、Gruvbox Dark、Solarized Dark、Solarized Light、One Dark、Tokyo Night（可含 Catppuccin Mocha 备选；最终清单产品确认）。
- 每套包含：fg/bg/cursor/selection + 16 色 ANSI；接入渲染器需要把固定调色板改为"每会话生效的调色板"。

**UI 入口**

- Settings → Appearance/Terminal：方案选择（色块预览）、颜色编辑（十六进制输入 + 取色）、字体族/字号、实时预览区。
- Session Editor → Appearance/Terminal：继承开关 + 覆盖值（D2）。
- **Folder Editor（新增最小版）**：右键文件夹 → "Edit Folder Defaults…"（`context-menu-design.md` §5.2 已规划），首版只放 Appearance/Terminal/Logging 三块；没有它，文件夹级配置无法落地。

**字体（已决策，见 §12）**

- 主字体：从**预设等宽字体列表**选择（不扫描系统全部字体）。
- 备用字体（回退链）：**允许自由配置**（CJK/emoji 回退可用）。
- CJK 回退是前置项，否则换字体后中文立即变方框（B1）。

**生效时机（已决策）**

- 所有主题变更**只对之后新开的终端生效**；已打开的终端保持原样（避免重排/PTY resize 抖动）。
- 字号变化会改变列宽行高 → 新终端按新 cell 尺寸计算列行数并初始 PTY resize。

### 6.4 可行性判断

- 渲染器改造（可配置调色板 + 字体加载）是主要成本；字体族支持与 CJK 回退是**已知硬点**（B1/B5）。
- 配置迁移与三级解析可完全单测覆盖，风险低。
- 附加项已决策不做：配色方案导入/导出、光标形状/闪烁留待后续迭代。

### 6.5 验收要点

- 同一文件夹下两个会话继承文件夹配色；对其中一个会话覆盖前景色后只影响它。
- 修改配置后**对之后新开的终端生效**；已打开终端不受影响；重启后配置保持。
- 分辨率缩放（DPI）下字号正确（注意 B5 遗留，建议先标注"高 DPI 待优化"）。

### 6.6 已决策（见 §12）

- 字体：主字体预设列表 + 备用字体自由配置（先补 CJK 回退）。
- 附加项：首版不做配色导入导出、不做光标形状/闪烁。
- 生效时机：只对之后新开的终端生效。

## 7. N6 终端日志：右键开启到指定文件

### 7.1 目标

- 终端右键菜单可对**当前标签**开启日志；弹窗让用户选择保存位置与文件名；开启后把所有终端打印记录写入该文件。
- 可随时停止；状态可见；异常可感知。

### 7.2 现状与差距

- 只有全局日志策略（配置驱动、自动命名），无运行中单标签开关，无右键入口，无"另存指定文件"。
- `SessionLogger` 已具备所需核心能力（路径、raw/sanitized、脱敏、轮转），扩展成本可控。

### 7.3 需求

- **入口**：终端右键菜单新增 `Start Logging…` / `Stop Logging` / `Open Log File` / `Open Log Folder`（与 `context-menu-design.md` §2 对齐；状态栏日志区域也提供同一入口，§9.2）。
- **开启弹窗字段**：
  - 保存位置（目录选择器；默认 = 上次使用目录，回退配置的 logs 目录）；
  - 文件名（默认模板如 `{session}-{timestamp}.log`，含非法字符校验；已存在时确认覆盖/改名）；
  - 格式：raw（含 ANSI 转义）/ sanitized（纯文本）——**默认 sanitized**；
  - 是否带时间戳（行首 `[HH:MM:SS]`）——**默认开**；
  - 是否记录本地输入（默认关；开启时按 tracker R-106 走单独确认）；
  - （可选）文件大小上限/滚动策略。
- **运行时行为**：
  - 记录从开启时刻起该会话的所有远端输出（不回写既有 scrollback；"导出当前 scrollback" 用独立 `Save Output As…` 入口）；
  - 定期 flush（如 1s 或按块）；标签关闭/会话断开/应用退出时**强制停止并 flush**，提示文件路径；
  - 写失败（磁盘满/路径失效）→ 状态栏与标签角标提示 + 自动停止策略（自动停并保留已写内容）；
  - 多标签可同时各自记录；标签/tab 徽标或状态栏显示"REC"。
- **停止**：右键同项变 `Stop Logging`，点击即关闭并提示文件位置（可点击打开）。
- **持久化**：临时日志为运行时会话态，不写配置；提供"保存为会话默认日志策略"的次级动作（写入 Session Editor 的 Logging 区，R-107）。

### 7.4 模型/配置变更

- `LoggingProfile` 扩展：`timestamps: bool`、`include_input: bool`、默认文件名模板（可复用 `PathTemplate`）。
- `SessionRuntime` 日志控制从"随配置创建"扩展为"运行中 open/close 任意路径"，提供 `start_logging(path, options)` / `stop_logging()`。
- 互斥规则（已决策）：同一会话同一时刻只有一个 transcript 输出；手动日志开启期间暂停自动日志（恢复后是否续写由用户动作决定）。
- 文件对话框依赖同 N1；WSLg 降级为路径输入。

### 7.5 可行性判断

- **低到中风险**：核心写入能力已存在，主要是 UI + 生命周期 + 错误处理。
- 风险点：退出时的 flush 与异常断电；多字节/ANSI 序列在 raw 模式下按字节写即可（现有实现为字节流）。

### 7.6 验收要点

- 开启后执行 `ls --color`，文件内可还原颜色（raw）或纯文本（sanitized）；停止后文件完整可打开。
- 断开、切标签、关闭应用后日志文件均完整（有结尾提示行可选）。

### 7.7 已决策（见 §12）

- 默认格式 sanitized + 时间戳开。
- 关闭标签/退出强制停止并 flush；同一会话单一日志输出（手动优先）。
- 关闭标签时如正在记录日志，先停止并 flush（与 N8 联动）。

## 8. N7 多窗口：标签移出成新窗口（状态保留）

### 8.1 目标

- 允许把终端标签移出当前窗口，生成一个新的操作系统窗口；原标签中的会话状态（SSH 连接、终端内容、scrollback、历史、日志、同步输入参与关系）**完全延续**。

### 8.2 现状与差距

- 单窗口 `run()`；窗口与运行时强绑定；没有窗口管理器概念；多标签前置（N0）也尚未落地。

### 8.3 需求（分阶段，已决策）

**阶段 1（先交付）**

- 窗口管理：支持创建/跟踪多个 `MainWindow` 实例；`run()` 改为 `show()` + `run_event_loop()`。
- 标签右键菜单："Move to New Window" / "Move to Main Window"（+ 快捷键），把标签（及其会话）迁移到目标窗口；**首版只做菜单，不做拖出手势**。
- 关闭带活动会话的窗口：确认后**直接断开其会话**（已决策）。
- 关闭最后一个窗口 = 退出应用。
- 每窗口一个活动标签与独立布局投影；应用级状态（会话表、传输队列、密钥、配置）共享；面板布局全局一套（N3）。
- 范围为**仅标签分离**，不做"新会话自动开新窗口"。

**阶段 2（原生拖出，等上游）**

- 真·拖到窗口外分离：等 **winit 0.31 正式版 + Slint 跟进版本**（Slint master 已实现跨窗口拖放，依赖 winit 0.31）；届时用 `DragArea`/`DropArea` 原生实现，同时可获得资源管理器 ↔ 应用的文件拖放。
- 反向合并（从子窗口拖回主窗口）随原生拖放一并评估。

**阶段 3（探索）**

- 窗口位置/大小记忆、多显示器恢复、窗口间同步输入联动的边界定义。

### 8.4 架构影响（需求级）

- 新增 `WindowManager`：持有 `Vec<WindowEntry>`，每个 entry = `MainWindow` 实例 + 该窗口的标签集合/活动标签/布局；`AppRuntime` 仍单实例共享（UI 单线程）。
- 终端刷新：建议保留单一应用级 Timer，遍历所有窗口/脏标签投影，避免 N 个 Timer 竞争（也便于同步输入 N9 的统一调度）。
- 主题与 UI 字体：Slint globals 按实例隔离 → 每个新窗口创建时应用主题/强调色/UI 字体，且主题变更时广播到全部窗口。
- 弹窗与焦点：模态弹窗归属触发窗口；应用级确认（退出等）归属当前焦点窗口。
- 状态保留的实现要点：迁移的只是 UI 所有权，`SessionRuntime`（含日志文件句柄、grid、shell）不重建；进入新窗口后按新 pane 的尺寸触发一次 PTY resize；远程编辑临时文件、传输队列引用不中断。
- 配置：`ui.multi_window.enabled`（默认开）、窗口几何记忆（可选）。

### 8.5 可行性判断

- Slint 多窗口能力**可用**，但当前应用是单窗口假设（回调、定时器、投影、主题应用都围绕一个 window），改造面大，评为 **XL/探索性**。
- WSLg 下多窗口截图与交互验证受限（E6），需要分平台验证计划。
- 明确不做：把不同窗口放到不同线程（Slint 单线程 UI 约束下的复杂度不值得）。

### 8.6 验收要点

- 执行 `Move to New Window` 后：终端画面/回滚缓冲/正在运行的命令状态不变，在新窗口继续交互；原窗口该标签消失且不影响其他标签。
- 两个窗口同时活动时输入、输出、resize、日志各自正确；退出一个窗口不影响另一个。
- 关闭带活动连接的窗口：确认框出现，确认后该窗口会话断开，不悬挂后台资源。

### 8.7 已决策（见 §12）

- 范围：仅标签移出/分离成新窗口；不含"新会话开新窗口"。
- 首版：只做右键"移动到新窗口"菜单；真拖出等 winit 0.31 + Slint。
- 关闭窗口：确认后直接断开。
- 布局：全局一套（所有窗口共享）。

## 9. N8 标签批量关闭

### 9.1 需求

- 标签右键菜单（顺序建议）：`Close`、`Close Others`、`Close Tabs to Left`、`Close Tabs to Right`、`Close All`、`Close Disconnected Tabs`。
- 启用条件与 `context-menu-design.md` §3 一致：无左侧/右侧标签时对应项 disabled（tooltip 说明原因）；`Close Disconnected Tabs` 仅在存在已断开标签时可用。
- 危险确认：批量关闭**包含活动连接**的标签时弹确认，显示将关闭数量与其中活动连接数量；纯已断开标签可直接关闭。
- 作用域：默认"当前 pane 内"；多窗格（E-029+）落地后菜单文案与行为按 pane 定义；应用退出仍走既有 Quit 确认。
- `Close All` 后若一个不剩，自动打开快速连接页（与 N2 一致）。
- 日志联动：关闭标签时如该标签正在记录日志，先优雅停止并 flush（与 N6 一致）。

### 9.2 验收要点

- 关闭顺序正确（Left/Right 以被点击标签为参照）；确认弹窗数量准确；取消不产生副作用；键盘/菜单入口行为一致。

## 10. N9 同步发送按键

### 10.1 需求

- 概念：某个终端为**源**，实时把输入按键/文本复制发送到**目标**终端（不是一次性命令广播）。
- 目标模式：
  - `Send to All`：当前作用域内所有已连接 SSH 终端；
  - `Send to Visible`：所有处于"可见 pane"中的终端（前端可见）；
  - `Send to Current`：取消同步（只保留当前终端），即退出同步状态。
- 入口：终端右键 `Send Key Input To…`（当前终端为源，弹出目标选择）/ `Stop Send Key Input To`（源端可见）；标签右键与 pane 头也可作为入口（contract §2.1/2.3）。
- 安全与状态（已决策，需回写契约）：
  - **不弹确认**；启动/进行中以状态栏 chip 常驻（`SYNC → 3 targets`）+ 一键停止，源/目标标签给角标；
  - `Ctrl+C` 等控制键广播时给出醒目的**非阻塞提示**（contract E-054 的确认方式调整为提示）；
  - 目标仅限已连接会话；断开自动移出并提示。
- 运行时：在所有终端输入路径的**唯一汇聚点**（`send_active_terminal_input/key/bytes`）上做扇出；对每个目标执行输入写入 + 输出轮询；保证输入顺序与源一致；不把目标自身的回显再回灌。
- 作用域：**当前窗口**（已决策）；多窗口（N7）落地后如需跨窗口再评估。
- 多 pane/分屏（E-029+）落地后，`Visible` 的判定 = 当前窗口内所有可见 pane 的终端。

### 10.2 模型/配置变更

- `InputSyncState { source: TabId, targets: BTreeSet<TabId>, mode: All | Visible | Selected }`（运行时会话态）。
- 每个标签可有 `receives_key_input: bool`（右键勾选 Receive Key Input，contract §2.3）。
- 不写配置（默认不持久化），可选记住"上次目标集合"作为偏好。

### 10.3 验收要点

- 源终端输入 `echo hi` → 目标全部得到同样输入及输出；停止同步后不再复制；目标断开自动退出集合；退出源标签同步自动停止。
- 高亮/角标/状态栏与真实状态一致，无"幽灵同步"；一键停止随时可用。

### 10.4 已决策（见 §12 与实现默认）

- 启动确认：不弹确认，状态栏提示 + 一键停止（偏离契约 E-052，需回写 `context-menu-design.md`）。
- 作用域：当前窗口。
- `Send to Current` = 取消同步。
- 实现默认：IME 组合在提交后才同步；不做"按住修饰键临时暂停同步"（如有异议可改）。
