# YShell 产品需求说明

## 1. 产品定位

YShell 是面向开发者、运维工程师、SRE、安全研究人员和需要长期维护远程主机的团队用户的开源终端客户端。它以 Tauri + xterm.js 为技术底座，提供本地终端、SSH 远程连接、会话管理、多标签页、多窗格、日志、脚本辅助和跨平台配置同步能力。

产品目标不是简单包装系统终端，而是构建一个可长期替代商业 SSH 客户端的桌面应用：既具备专业会话管理能力，又保留开源项目的可审计性、可扩展性和社区协作空间。

## 2. 目标用户

### 2.1 个人开发者

- 需要频繁连接云服务器、开发机、容器或跳板机。
- 关注启动速度、字体渲染、快捷键、命令历史和本地终端体验。
- 希望配置可导出、可迁移，避免被单一商业软件绑定。

### 2.2 运维与 SRE

- 管理大量主机、环境和账号。
- 需要会话分组、批量连接、广播输入、日志审计、跳板机、代理和密钥管理。
- 需要在 Windows、Linux、macOS 上获得一致的操作习惯。

### 2.3 团队与企业用户

- 需要共享连接模板、统一命名规范、最小权限访问和审计能力。
- 关注配置加密、凭据隔离、权限边界和可控的更新策略。
- 需要后续扩展插件、命令片段、脚本库或团队配置源。

## 3. 核心场景

### 3.1 快速连接远程主机

用户通过快速连接面板输入主机、端口、用户名、认证方式和可选代理后，可以立即打开 SSH 会话。连接成功后，会话可保存为持久配置，也可以作为一次性临时会话存在。

验收标准：

- 支持主机、端口、用户名、密码、私钥、私钥口令和连接别名。
- 支持连接前测试和连接失败原因展示。
- 临时连接可以一键保存为正式会话。

### 3.2 会话树管理

用户通过左侧会话树管理所有远程连接，支持文件夹、标签、搜索、复制、移动、导入、导出和批量编辑。

验收标准：

- 支持多级文件夹和拖拽排序。
- 支持按名称、主机、用户名、标签、最近连接时间过滤。
- 支持会话复制、模板创建和批量修改端口、代理、认证方式等字段。

### 3.3 多标签页与分屏工作

用户可以像 Xshell 一样在一个窗口中打开多个会话标签页，并在同一标签页内进行横向或纵向分屏，以便同时观察多个主机状态。

验收标准：

- 标签页支持新建、关闭、重命名、锁定、拖拽排序、拖出新窗口。
- 分屏支持水平、垂直、等分、关闭当前窗格、最大化当前窗格。
- 支持将同一命令广播到当前标签页的多个窗格或选中的多个会话。

### 3.4 本地终端

用户可以打开本地 Shell，会话能力与远程 SSH 会话保持一致，包括标签页、分屏、配色、字体、复制粘贴和日志。

验收标准：

- Windows 默认支持 PowerShell，可配置 CMD、Git Bash、WSL 或自定义 shell。
- Linux/macOS 默认读取用户登录 shell，可配置启动命令和工作目录。
- 本地终端与远程终端共享 xterm.js 渲染设置。

### 3.5 日志与回放

用户可以为会话开启文本日志，后续扩展为终端回放和审计日志。

验收标准：

- 支持手动开始/停止日志。
- 支持按会话、日期、主机自动命名日志文件。
- 日志路径、编码、换行符和敏感输入过滤策略可配置。

### 3.6 文件传输

MVP 后支持 SFTP 文件面板，用户可在当前 SSH 连接基础上上传、下载、重命名、删除远程文件。

验收标准：

- 可从会话打开对应 SFTP 面板。
- 支持拖拽上传和下载队列。
- 文件操作失败时保留错误信息和重试入口。

## 4. 功能范围

### 4.1 MVP 必须包含

- 本地终端。
- SSH 连接。
- 会话树与快速连接。
- 多标签页。
- 基础分屏。
- 基础主题、字体、配色方案。
- 密码与私钥口令的安全存储。
- 配置导入导出。

### 4.2 第二阶段包含

- 广播输入。
- 会话日志。
- 跳板机与代理。
- SFTP 基础文件传输。
- 命令片段与快捷命令。
- 会话模板与批量编辑。

### 4.3 暂不纳入早期范围

- 完整 RDP/VNC 客户端。
- 云端团队后台。
- 复杂自动化编排平台。
- Web 版多人协作终端。
- 内置密码管理器替代品。

## 5. 非功能需求

### 5.1 跨平台

- Windows、Linux、macOS 均需支持主流程。
- 允许在本地 shell 启动、系统钥匙串、窗口行为、菜单栏和通知等系统集成能力上做平台适配。
- 自动化测试应覆盖主要平台逻辑，发布前使用平台矩阵构建安装包。

### 5.2 性能

- 应用冷启动目标小于 2 秒，复杂环境下不得超过可接受桌面应用启动体验。
- 单窗口至少支持 20 个标签页和 6 个可见终端窗格。
- xterm.js 渲染需要避免 React/Vue/Svelte 状态频繁重绘终端内容。

### 5.3 可用性

- 常用操作必须有菜单、快捷键和命令入口。
- 连接失败、认证失败、主机密钥变化等情况必须提供清晰提示。
- 终端区域必须优先保证输入延迟低、字体清晰、复制粘贴可预测。

### 5.4 安全

- 密码、私钥口令、代理凭据默认不以明文保存。
- 配置导出默认不包含敏感凭据，除非用户显式选择加密导出。
- 主机密钥校验必须可见、可确认、可撤销。
- 日志功能应提示可能记录敏感输出。

### 5.5 可维护性

- 前端 UI、终端渲染、会话状态、协议层和配置存储应分层。
- IPC 命令需有明确输入输出类型。
- 关键业务对象使用稳定 ID，避免 UI 名称变化导致引用失效。

## 6. 成功指标

- MVP 可稳定完成本地终端和 SSH 连接的日常使用。
- 用户可以从零创建、保存、搜索和重连会话。
- 终端输入延迟、复制粘贴、窗口布局和快捷键达到可长期使用水平。
- 项目文档足够清晰，社区贡献者可以基于文档理解模块边界并开始实现。
