# YShell 路线图与里程碑

## 1. 项目管理原则

当前目标是从“可编译发布”转为“专业 SSH 客户端可用”。路线图按风险和用户价值排序：先确保终端和 SSH 稳定，再完成会话管理和 Xshell 类工作流，最后扩展 SFTP、隧道和团队能力。

每个阶段必须满足：

- 有明确功能清单和验收标准。
- P0 安全项不得延期到后续阶段。
- 阶段结束必须更新设计差异和未完成项。
- 不允许用“占位实现”通过验收；占位 UI 必须标记为未完成。

## 2. M0：设计重置与验收基线

目标：删除旧的阶段性闭环叙述，建立完整产品设计、交互、架构和验收标准。

交付物：

- 产品需求说明。
- 体验与交互设计。
- 技术架构设计。
- 验收标准矩阵。
- 项目路线图。

退出条件：

- 研发和测试可以从文档拆分 issue。
- 每个核心功能都有可验证的 Given/When/Then。
- 文档明确现有代码不符合时以文档为准。

## 3. M1：终端基础可用

目标：本地终端达到日常可用，建立后端 runtime 生命周期和强类型 IPC。

功能：

- 本地 PTY open/write/output/resize/close。
- xterm.js 封装、复制粘贴、搜索、链接识别。
- 标签页基础操作。
- 设置持久化：默认 shell、字体、字号、主题、滚动行数。
- 进程清理和应用退出管理。

验收：

- `AC-LOCAL-001` 至 `AC-LOCAL-006` 全部通过。
- `AC-TAB-001`、`AC-TAB-002` 通过。
- `AC-SET-001` 通过。

## 4. M2：SSH 与安全基线

目标：SSH 连接真实可用，认证、主机密钥和凭据安全满足 P0。

功能：

- 快速连接。
- SSH 密码、私钥、Agent、键盘交互。
- 主机密钥未知/变化处理。
- SSH resize、超时、保活。
- 凭据不落普通配置、导出和日志。
- 连接失败可恢复。

验收：

- `AC-QC-001` 至 `AC-QC-005` 通过。
- `AC-SSH-001` 至 `AC-SSH-007` 通过。
- 所有连接失败场景不得清空用户输入或导致应用崩溃。

## 5. M3：会话管理达到 Xshell 类基础体验

目标：大量会话可组织、搜索、编辑、导入导出。

功能：

- 会话树、文件夹、拖拽排序。
- 会话新建、编辑、删除、复制、重命名。
- 收藏、最近连接、标签、搜索。
- 导入预览、导出脱敏。
- 会话编辑器完整分组表单。

验收：

- `AC-SESSION-001` 至 `AC-SESSION-010` 通过。
- `AC-QC-006` 通过。
- 配置迁移和原子写入测试通过。

## 6. M4：多标签、多分屏和高风险输入控制

目标：形成专业终端工作台，可以同时管理多个远程会话并安全批量操作。

功能：

- 标签排序、锁定、关闭其他、克隆、重命名。
- 横向/纵向分屏、焦点切换、分隔条 resize。
- 广播输入、目标选择、多行确认、危险命令确认。
- 布局模板首版。

验收：

- `AC-TAB-003`、`AC-TAB-004` 通过。
- `AC-SPLIT-001` 至 `AC-SPLIT-004` 通过。
- `AC-BROADCAST-001` 至 `AC-BROADCAST-005` 通过。
- 广播误操作防护不得有 P0/P1 缺陷。

## 7. M5：日志、SFTP 和文件传输

目标：补齐运维常用的审计和文件操作能力。

功能：

- 手动/自动日志。
- 日志模板、日志状态、打开日志目录。
- SFTP 双栏面板。
- 上传、下载、删除、重命名、冲突处理、传输队列。

验收：

- `AC-LOG-001` 至 `AC-LOG-005` 通过。
- `AC-SFTP-001` 至 `AC-SFTP-005` 通过。
- 日志脱敏测试通过。

## 8. M6：高级连接能力

目标：覆盖复杂网络环境和开发调试场景。

功能：

- 本地、远程、动态端口转发。
- HTTP/SOCKS 代理。
- 单级和多级跳板机。
- 自动重连增强。
- 转发状态面板。

验收：

- `AC-TUNNEL-001` 至 `AC-TUNNEL-003` 通过。
- `AC-PROXY-001` 通过。
- `AC-JUMP-001`、`AC-JUMP-002` 通过。
- 代理和跳板机凭据不落普通配置。

## 9. M7：打磨、跨平台和公开 beta

目标：达到公开 beta 品质。

功能：

- 快捷键完整自定义。
- 高对比主题和可访问性。
- 导诊断信息和脱敏。
- Windows/macOS/Linux 安装包和自动更新策略。
- 性能优化和长期稳定性测试。

验收：

- P0 全部通过，P1 通过率不低于 95%。
- 跨平台手测矩阵完成。
- 单终端 10,000 行输出、多窗格输出和 1 小时稳定性测试通过。

## 10. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 继续堆 UI 占位但连接不可用 | 产品无法使用 | 每个功能必须绑定验收测试，不允许占位通过。 |
| SSH 技术选型不满足认证/host key | 安全和兼容性失败 | M2 前完成 OpenSSH 与 Rust SSH 库 spike，并用验收矩阵决策。 |
| 终端输出进入前端全局状态 | 卡顿和内存泄漏 | 输出事件直写 xterm，状态只存元数据。 |
| 凭据误写配置或日志 | 严重安全问题 | 建立明文扫描、脱敏测试、凭据存储封装。 |
| 跨平台 PTY 差异 | 行为不一致 | platform 层隔离，M1 即建立三平台冒烟用例。 |
| 广播输入误操作 | 用户生产事故 | 强提示、确认、目标选择和危险命令检测作为 P1 门禁。 |

## 11. 建议 issue 拆分

- `product/acceptance`: 将验收矩阵转为测试计划。
- `frontend/shell-layout`: 主窗口、侧边栏、标签栏、状态栏。
- `frontend/session-editor`: 会话编辑器和快速连接。
- `frontend/terminal`: xterm 封装、搜索、复制粘贴。
- `frontend/workspace`: 标签、分屏、布局。
- `backend/runtime`: runtime registry 和生命周期。
- `backend/pty`: 本地 PTY。
- `backend/ssh`: SSH、认证、host key、keepalive。
- `backend/config`: 配置模型、迁移、导入导出。
- `backend/credentials`: 系统安全存储和脱敏。
- `backend/logging`: 终端日志和审计事件。
- `backend/sftp`: SFTP 和传输队列。
- `backend/tunnel`: 端口转发、代理、跳板机。
- `qa/e2e`: 验收矩阵自动化和跨平台手测。
