# YShell 路线图与里程碑

## 1. 路线图原则

YShell 的迭代顺序应先保证“终端可用、连接可靠、会话可管理”，再扩展“效率工具、文件传输、团队能力”。每个阶段都需要有清晰验收标准，避免在基础体验不稳定时过早堆叠高级功能。

## 2. 阶段 0：设计与工程基线

目标：建立产品、交互、架构和工程约束。

交付物：

- 产品需求说明。
- 体验与交互设计。
- 技术架构设计。
- 路线图和里程碑。
- 初始工程模板与目录结构决策。

验收标准：

- 贡献者能够从文档理解 MVP 范围。
- 前后端模块边界、IPC 方向和安全策略清晰。
- 后续 issue 可以映射到具体模块和里程碑。

## 3. 阶段 1：本地终端 MVP

目标：完成可日常使用的跨平台本地终端。

功能：

- Tauri 应用壳。
- xterm.js 终端渲染。
- 本地 PTY。
- 标签页。
- 基础主题、字体、配色。
- 复制粘贴、搜索、resize。
- 设置持久化。

验收标准：

- Windows、Linux、macOS 均可打开本地 shell。
- 终端输入输出稳定，窗口 resize 后行列数正确。
- 关闭标签和退出应用时不会残留后台进程。
- 基础设置重启后保持。

## 4. 阶段 2：SSH 与会话管理 MVP

目标：完成 SSH 客户端核心能力。

功能：

- 快速连接。
- 会话树。
- SSH 密码认证。
- SSH 私钥认证。
- SSH Agent 认证。
- 主机密钥校验。
- 会话保存、编辑、删除、复制。
- 配置导入导出。
- 系统安全存储集成。

验收标准：

- 用户可以创建 SSH 会话并稳定连接远程主机。
- 未知主机密钥和主机密钥变化均有明确提示。
- 密码和私钥口令不以明文写入普通配置文件。
- 导出的默认配置不包含秘密内容。

## 5. 阶段 3：专业终端工作流

目标：接近 Xshell 的高频操作逻辑。

功能：

- 分屏。
- 会话分组和标签过滤。
- 最近连接和收藏。
- 广播输入。
- 多行粘贴确认。
- 会话日志。
- 命令片段。
- 快捷键自定义。

验收标准：

- 一个窗口内可稳定管理多个标签页和多个窗格。
- 广播输入状态明显，危险粘贴有确认。
- 日志可按会话自动命名并手动停止。
- 快捷键冲突可检测并提示。

## 6. 阶段 4：文件传输与高级连接

目标：补齐远程维护常用能力。

功能：

- SFTP 文件面板。
- 上传、下载、删除、重命名。
- 传输队列。
- HTTP/SOCKS 代理。
- 跳板机。
- 端口转发。
- 连接保活与自动重连策略。

验收标准：

- 可从 SSH 会话直接打开 SFTP 面板。
- 文件传输失败可重试并保留错误信息。
- 跳板机和代理配置可复用到多个会话。
- 端口转发状态可见、可停止。

## 7. 阶段 5：可扩展与团队能力

目标：让项目从个人工具演进为可扩展平台。

功能：

- 插件 API 草案。
- 命令面板扩展。
- 会话模板。
- 团队配置源草案。
- 审计日志增强。
- 配色和主题包生态。

验收标准：

- 外部贡献者可以实现有限范围插件或扩展。
- 团队可以共享不含秘密的会话模板。
- 审计日志与终端日志边界清晰。

## 8. 主要风险与缓解

| 风险 | 影响 | 缓解策略 |
| --- | --- | --- |
| 跨平台 PTY 差异 | 本地终端行为不一致 | 早期建立平台矩阵测试，隔离 platform 模块。 |
| SSH 库能力不足 | 认证、代理或 SFTP 受限 | 在阶段 2 前完成技术选型 spike。 |
| xterm.js 性能问题 | 多窗格场景卡顿 | 避免终端输出进入全局状态，使用事件流直写终端。 |
| 凭据存储不一致 | 安全和用户体验受影响 | 提供平台优先方案和 Linux 降级提示。 |
| 类 Xshell 体验边界过大 | MVP 延期 | 先实现会话树、标签页、快速连接和 SSH，再扩展高级功能。 |
| Fluent Design 过度装饰 | 终端可读性下降 | 终端区域以纯色和高对比为默认，材质效果只用于外层 UI。 |

## 9. 建议 issue 拆分

- `design/product`: 产品需求和 MVP 范围。
- `design/ux`: 主窗口、会话树、标签页和分屏交互。
- `design/architecture`: IPC、PTY、SSH、配置、安全存储。
- `frontend/shell`: Tauri 前端壳与基础布局。
- `frontend/terminal`: xterm.js 包装层。
- `backend/pty`: 本地 PTY。
- `backend/ssh`: SSH runtime。
- `backend/config`: 配置与迁移。
- `backend/security`: 凭据和主机密钥。
- `qa/e2e`: 跨平台端到端测试。
