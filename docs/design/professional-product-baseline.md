# YShell 专业产品基线与验收门禁

## 1. 原则

YShell 的目标是开源版 Xshell 类 SSH 工作台。后续实现不得用“看起来有点像终端工具”的低标准验收，而必须先回答：真实运维人员能否用它长期管理服务器、审计连接、降低误操作风险，并用一致的菜单、属性页和快捷键完成任务。

## 2. 立即生效的产品门禁

1. **先建模再开发**：任何会话、标签、分屏、广播、日志、认证能力必须先说明对象模型、状态流、入口位置、错误态和退出态。
2. **不允许单点补丁式交付**：用户指出一个问题时，必须追溯同一产品域的相邻缺口。例如“不能设置密码”必须同时检查会话属性页、凭据保存策略、导入导出脱敏、连接时认证流和编辑已有会话。
3. **敏感信息安全边界**：密码、私钥口令、代理密码不得进入普通配置文件和导出文件。若提供临时密码输入，只能用于当前连接过程；长期保存必须使用系统凭据库或等价安全存储。
4. **Xshell 类信息架构**：连接配置归入“会话属性”，工作区操作归入菜单栏/工具栏/标签上下文，不能把核心设置散落在临时按钮或系统 prompt 中。
5. **视觉和滚动门禁**：主窗口、侧栏、标签、工作区和终端必须共用同一深色 token；终端不得撑破 pane，不得出现 body、workspace、xterm 多层滚动条互相竞争。

## 3. 会话属性的最低可用范围

当前仅实现 SSH 和本地 Shell，但 SSH 会话属性至少必须包含以下分组：

| 分组 | 本阶段必须有 | 后续完善 |
| --- | --- | --- |
| 常规 | 名称、协议、摘要 | 图标、颜色、描述、标签 |
| 连接 | 主机、端口、用户名、主机密钥策略 | 超时、保活、压缩、启动命令 |
| 用户身份验证 | 密码/键盘交互、私钥、SSH Agent；本次连接密码输入 | 系统凭据库存储、私钥口令、Kbd-interactive 多因子 |
| 终端 | 继承全局终端设置并明确展示 | 会话级字体、编码、终端类型、环境变量 |
| 日志 | 继承全局日志策略并明确展示 | 会话级自动日志、模板、脱敏 |

## 4. 密码认证验收

- 用户选择 SSH 密码认证时，必须看到明确的密码输入位置，而不是只能猜测“去终端里输入”。
- 本阶段若填写密码，后端只能把该密码用于当前 OpenSSH 密码提示的自动应答，不写入 SessionProfile、不落盘、不导出。
- 若用户保存会话，只保存认证方式为 password；下次连接可重新输入密码或留空后在终端提示中手动输入。
- 后续系统凭据库完成后，属性页应把“临时密码”升级为“保存到凭据库/每次询问/清除凭据”的三态策略。

## 5. 实施验收清单

每次交付必须至少说明：

1. 改动对应的产品域和相邻域是否一起审视。
2. 敏感字段是否可能进入 localStorage、普通 JSON 配置、导出文件、日志或错误消息。
3. 菜单入口、工具栏入口、属性页入口是否一致。
4. 失败态是否可理解，是否避免用户以为配置已经保存但实际未生效。
5. typecheck、build、Rust 编译或受限原因是否记录。
